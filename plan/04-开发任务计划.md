# 04 开发任务计划

编写日期：2026-10-02。所有任务状态为 **TODO**。阶段名称 P0–P4 表示实施顺序。任务定义的是未来交付，不是已完成事项。

完整目标是可演示、可重跑评测、能说明工程取舍的 Agent 原型。先完成单 Agent 完整业务闭环，再增加记忆、委派与运营能力。OTA 合作资格单列条件任务，避免核心工程因第三方审批停摆。

## 关键依赖与范围控制

主路径：`T00 → T01 → T02/T03 → T04/T05 → P1 → P2 → P3 → P4`。

最早可演示版本是 T17，重点是完整单 Agent 路径；完整技术展示要包含 T28、T37、T44。T17 之后继续推进深度能力，不能把第一版页面当成最终目标。

第二优先级：向量检索、委派、SQL 分析、多供应商、天气/门票。它们应有实验或具体需求依据；关闭无收益能力也是需要记录的工程决策。

未排真实日期和工期：当前团队人数、可用时间及 API 审批周期未知。进入实施时按实际投入安排迭代，每次选择能形成可验收垂直切片的任务，不承诺未经估算的完成日期。

## 每个任务完成时记录什么

任务记录至少包含：实现提交、关键文件、输入与运行命令、测试/评测输出、失败与修复、当前限制、是否涉及真实数据。禁止只把复选框改成完成而没有可验证材料。
