# 05 评测与验收

从 M0 建立用例；按业务结果和状态验收，允许不同的合法工具路径。

## 1. 三层验证

| 层次 | 方法 | 能回答的问题 |
| --- | --- | --- |
| 确定性工程回归 | 假 client、fixtures、真实测试数据库、故障钩子 | 调度、校验、事务、恢复是否按契约工作 |
| Agent 任务评测 | 固定状态快照 + 用户输入 + 允许结果 | 模型在工具与约束下能否完成任务 |
| 外部接口核验 | 获授权的 contract/sandbox/live smoke | 当次真实协议、字段与覆盖是否可用 |

样例保存：case_id、初始 request/plan/messages/skill/evidence、用户输入、fixture 版本、故障触发点、允许最终状态、禁止副作用、预期卡片字段与 rubric。大部分从预构造状态进入；状态跨轮本身是被测行为时才保留多轮。模拟用户可发现问题，正式评测转成可重放样例。[上游 eval 规则](../../../commerce-agents/plugins/commerce-builder/skills/commerce-evals/SKILL.md)

## 2. 核心回归矩阵

| ID | 场景 | 必须断言 |
| --- | --- | --- |
| R01 | 分段/截断参数、未知工具、接口错误 | 未完整参数不执行；状态与错误可追踪 |
| R02 | 工具往返中断、保存后续接 | 无未配对调用；供应商续接字段保留 |
| R03 | 多工具读取、读取依赖写入 | 并发有上限；写屏障生效；新条件提交前不查新报价 |
| R04 | RequestPatch 缺省、clear、纯解释提问 | 未改字段保留；清空有效；解释不递增条件 revision |
| R05 | 伪造/跨用户/过期/错日期 evidence | 不用于事实卡片；无来源字段为 unknown |
| R06 | 闭馆、预算缺项、跨午夜、路线失败 | conflict 与 unknown 分开；不静默放宽硬条件 |
| R07 | 局部替换景点、重复访问地点、锁定项 | item_id 稳定；无关项保持；相邻路线和全局预算重查 |
| R08 | 草稿确认、版本冲突、重复点击 | owner/base_version/revision 正确；只增加一个计划版本 |
| R09 | 提交前崩溃、提交后响应前崩溃 | 未提交可重试，已提交读幂等结果，无重复写入 |
| R10 | 同 revision 两个 attempt、旧 worker 晚到 | 旧 attempt/过期租约不能提交；校验和写入原子 |
| R11 | SSE 断连、重复事件、保留窗口外重连 | 无工具重执行，前端去重/快照恢复，最终状态正确 |
| R12 | 取消、改条件、429、超时、预算耗尽 | 旧结果不覆盖，重试有限，失败不冒充零结果 |
| R13 | 长历史压缩后继续规划及 worker 恢复 | 关键条件、skill、证据与工具配对正确；模型可继续 |
| R14 | 记忆查看/删除与异步提取竞争 | 用户隔离；generation 检查与写入同事务；不复活删除内容 |
| R15 | 恶意文章/工具文本 + 对应正常文本 | 不扩大工具/权限或写记忆；正常任务仍能服务 |
| R16 | 规划子 Agent 正常、超时、越权、迟到、恢复 | 固定快照/白名单/父级预算生效；无写入，父端重验、可控回退；即使默认关闭仍测实验路径 |
| R17 | 五类根因注入、连带错误与正常拦截对照 | 关联正确、首个偏离点可定位、证据不足为 unknown；修复后原 case 和邻近正常例通过 |
| R18 | 队列满、并发准入、429、超时、取消/过期竞争 | 容量不超配，拒绝不撤销原任务；重试有界、槽位可释放、队列可排空；无重复写入 |
| R19 | MCP 扩展启用时 | 鉴权/契约/错误一致；未实现标 N/A，不计通过 |

每项关联 test、case_id 和任务 ID；保留上游工具配对、非法参数、来源、展示与循环上限回归，改变的行为写替代断言。

恢复测试使用数据库和可控制的 crash hooks，不能只有 mock 掉持久化层的单测。至少一个接口到 worker 到数据库到事件的集成流程，以及一个 Web 确认/重连关键流程。

## 3. 数据集与评分

M0 约 12 个开发样例先跑通；逐步形成建议 60 个业务样例：20 dev、40 冻结 test。具体规模和分桶在第一次正式比较前锁定。协议/故障单测独立维护，不与业务成功率混算；扩展未启用不凑样本数。

覆盖正常、矛盾/长历史、日期/人数变化、酒店费用/退款缺失、局部改程、恢复与偏好。每个“应拒绝/应澄清”用例有一个“应服务/条件足够”的对应例，避免靠一律拒绝提高正确率。

| 指标 | 定义 |
| --- | --- |
| Task completion | 完成全部预定结果的任务 / 适用任务；部分完成单列 |
| Fact precision / coverage | 有证据且字段正确的断言比例 / 必需事实被覆盖的比例；避免少说就高分 |
| Constraint pass | 满足全部可核验硬条件的方案比例；未知和冲突分别统计 |
| Resume completion | 可恢复故障中，经恢复完成原目标的任务比例 |
| Graceful degradation | 无法继续的故障中，正确保留成果并说明缺口的比例 |
| Context / memory | 硬条件保留、错误沿用、应记/不应记/删除行为分别计数 |
| Cost / latency | 全任务口径、分位数及未知用量处理见第 7 节 |
| Quality rubric | 相关性、解释和取舍；人工抽查，模型 judge 只辅助 |

分母、样本数、失败 case 和跳过原因都展示。judge 无法解析单列 judge_error，不当 Agent 成功或失败。没有实际调用的 API 不填写准确率。

## 4. 基线与消融

- B0：纯模型，展示无外部信息时的限制，不把全部差距归因于 Agent。
- B1：检索问答，比较建议质量。
- B2：单主 Agent + 工具 + 约束校验，作为主要工程基线。
- B3：B2 + 已实现的上下文/记忆优化，仍为单主 Agent。
- B4：B3 + 受限规划子 Agent；父端工具、事实与约束能力不变，额外调用计入同一总预算。

同时做“同一候选与事实都给各组”的决策对照；固定模型、思考参数、数据与总预算。每次只关闭一项：Skills 按需加载、压缩、长期记忆、validator、checkpoint 或委派。危险消融仅在隔离 fixture/测试数据库执行。

Skills 对比质量、加载轮次、token 和延迟；MCP 比较契约与运维代价；委派按下一节。

## 5. 规划子 Agent：必须交付的对照

实验开始前登记 eligible 任务条件、配置与可接受代价；按简单规划、复杂约束、局部改程分桶。对同一快照分别跑 B3/B4，固定模型/思考参数、候选、证据时间、可用工具和总 token/工具/费用/期限上限；两组都可访问相同事实，不给子 Agent 额外优质数据。

每个 case 每组至少重复 3 次，交替顺序并记录缓存条件。报告完成/约束通过、局部保留率、模型轮次、全量 token/费用、P95、回退与预算耗尽率；包括主端收尾、子端失败及重试。独立样本与重复数分开。

报告逐 case 差异、分桶与波动，小样本不宣称显著。仅在安全/一致性不退化、有质量或上下文隔离收益、成本/时延不超预登记上限时，在指定任务范围开启；否则记录关闭决定。数据集规则见第 8 节。

## 6. Trace 归因：从失败到修复

每个最小归因样例仅注入一个明确故障，覆盖条件误解、错误工具/参数、供应商异常、过期证据、提交错误；再增加多故障链与正常拦截对照。测试集附预期根因、首个偏离点及应存在的证据；查看者先从 Trace 判断，再对照答案。

| 要判断什么 | 必须查的证据 |
| --- | --- |
| 用户说了两晚，系统却查三晚 | 用户轮次、RequestPatch 前后值、查询参数，先确定在哪层改变 |
| 选错工具或缺参数 | 当轮已知条件、工具描述/前置条件、调用与错误；不把其他合法路径判错 |
| 供应商故障 | 请求 ID、响应/超时、重试时序与期限；区分成功恢复与最终失败 |
| 证据过期 | evidence 有效期、查询条件指纹、使用时间和拦截结果 |
| 状态提交问题 | run/attempt/租约、预期/实际版本、事务结果和最终状态；正常冲突拒绝另计 |

产物是一条 `case_id → trace → 根因及依据 → 修复提交 → 原 case + 邻近回归` 记录。模型可辅助分类，人工确认根因；证据不足记 unknown。记录归因覆盖率、核对正确率、unknown/误判数，以及一次独立定位用时；注入实验结果与真实 Bad Case 分开，不把全都分到某一类当作正确。

冻结复现输入；修复后跑原故障及邻近正常/边界用例，分别评恢复、合理拒绝和业务完成。

## 7. 性能实验：负载、计时与过载

先用假模型和定延迟 fixture 测宿主/数据库/队列/SSE，再小并发核验真实 DeepSeek。模拟吞吐与估算费用单列。

| 项目 | 实验规则 |
| --- | --- |
| 工作负载 | 建议短查询/完整规划/局部改程为 40%/40%/20%；每轮固定数据、任务比例、输出上限及缓存状态，简单任务不得掩盖复杂任务退化 |
| 并发阶梯 | 从 1/5/10/20 个在途请求起测；固定 worker/执行槽/连接池。单 worker 基线先做，多 worker 对比单独配置 |
| 样本与时长 | 建议预热 30 秒、稳定段至少 3 分钟，至少 3 轮；记录每桶样本数。样本不足就延长或标探索性结果，不用极少任务的 P95 作结论 |
| 负载方式 | 固定并发测常态；额外用固定到达速率/突发流量制造积压，即使系统变慢也继续按计划发请求，记录发生器滞后和客户端错误 |
| 故障方式 | 注入供应商 429/Retry-After、慢响应/不可用、worker 暂停；验证队列满、排队取消/过期和恢复后的排空时间 |
| 范围与预算 | 先在本地替身上跑完整矩阵；真实服务只跑授权额度内的小样本。事先配置费用上限和停止条件，未跑的阶梯明确标注 |

时间戳：`t_received / t_admitted / t_started / t_first_progress / t_first_valid_result / t_terminal`。宿主持久化关键时点，客户端独立记录接收到事件的时间；同机耗时用单调时钟，跨进程时钟需同步/标明误差。

| 必报指标 | 口径 |
| --- | --- |
| 排队时间 | 首次 started − admitted；后续退避/再排队分段累计另报。未启动的过期/取消任务单列等待时长，不从分母隐去 |
| 首反馈时间 | 首个有实际工作含义的进度 − received；即时 ACK/心跳不计，另报首个校验通过的业务结果时间 |
| 端到端 P50/P95 | terminal − received，包含排队与重试；分别给成功任务和全部已结束任务分布，未结束数/等待时间单列 |
| 错误率与完成 | 分列入站、准入、429/503、系统失败/超时/过期、取消、partial、业务完成；拒绝率=(429+503)/入站，任务失败率=系统失败/准入，未终结单列。供应商尝试错误率另报 |
| 吞吐与队列 | 每秒接受/完成任务、业务成功吞吐、队列长度/最老等待、执行槽位、DB 池等待、过载恢复排空时间 |
| 成本 | 报告任务级费用分布，以及总费用 / 接收成功数、总费用 / 完成数；含摘要、子任务、失败和重试，token 同报；未知用量、模拟估算单列 |

按任务/轮次报样本和分布，总体 P95 从原始观测/直方图算，不平均各桶 P95。首进度与有效结果分开解释；记录硬件、worker/槽位、数据库和模型配置。

先过 R18 的容量/预算/提交/恢复门禁，再看预登记的排队、首结果、P95、错误率和成本阈值；失败时用 Trace 分解排队/模型/工具/数据库耗时，单变量调整后回测。

## 8. 运行与门禁

统一规则：结果绑定 repo/data/prompt/skill/schema/provider/model 与价格快照；只用 dev 调优，冻结 test 至少重复 3 次，报告独立样本数、重复数及波动。

硬门禁：适用的 R01–R18 指定必过用例全部通过；跨用户读取、旧结果覆盖、重复计划写入必须为零。R16 测试实验路径，不因默认关闭跳过；R19 在 MCP 扩展实现时必过。模型任务成功率、延迟和预算阈值在 M0 基线后、正式优化前锁定并记录理由，不预填改善百分比。

拟建命令（当前未实现）：
```text
python -m eval.run --config eval/configs/baseline.yaml --split test
python -m eval.faults --suite recovery --data-mode fixture
python -m eval.compare --runs <run_ids>
python -m eval.faults --suite attribution --data-mode fixture
python -m eval.load --config eval/configs/load-fixture.yaml
python -m eval.run --config eval/configs/planner-comparison.yaml --split test
```

离线 CI 跑静态检查、协议/领域/数据库测试与前端构建；模型评测和 live smoke 独立限额触发，不让第三方网络波动冒充代码回归。

M4.5 三套演示各附正常/失败结果、Trace、复现命令和测试；报告收益、代价与剩余 Bad Cases。
