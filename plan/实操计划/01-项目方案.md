# 01 项目方案

## 1. 产品与范围

做一个独立旅游规划网站，帮助读完攻略的用户结合日期、同行人、预算和交通方式，比较酒店、安排并修改行程、保存方案。

第一版：日本一个城市、2–3 天、中文交互。城市暂定京都，M0 确认；不做航班、跨城联程或真实下单。运营台、主动营销、多人协作及任意代码执行不进入第一版。

Agent 设计参考 Commerce Agents，业务背景参考 DataMind 的旅游内容推荐；[来源与复用依据](06-来源与待验证事项.md)。采用一个主 Agent 持有对话，配合 Skills、工具执行器、业务后端和展示工具；受限规划子 Agent 做对照实验，是否启用由结果决定。

## 2. 用户交互

独立 Next.js 网站包含文章示例页、规划工作台、保存的行程页，以及开发者调试页。无需嵌入其他旅游网站。

1. 从攻略进入：“两个大人一个孩子，住两晚，不租车。”保留已知信息，仅在查询需要时确认日期、儿童年龄和房间数。
2. 查询内容、地点和酒店，同口径比较住宿；卡片显示来源、获取时间和数据模式。
3. 模型提出行程，代码检查日期、路线、预算及开放信息；未知信息与硬约束冲突分别展示。
4. 用户要求“只把第二天下午换成室内活动”，生成局部差异，保留无关安排。
5. 用户确认后保存新版本，重复确认返回同一结果。
6. 断线或重启后恢复任务；打开历史计划时标明需要刷新的报价。接口失败允许展示部分成果及缺口。

先用自制 fixtures 完成闭环，再接入可获权限的真实数据；固定报价不作为实时可订信息。来源和接入限制见 [03](03-数据工具与外部API.md)。

## 3. 技术组件

| 组件 | 技术与职责 |
| --- | --- |
| Web | Next.js/React：对话、比较卡片、行程差异、确认与 SSE |
| API / TaskHost | FastAPI：身份、消息、任务生命周期、事件重放、确认保存 |
| TravelAgent / ModelProvider | Python/asyncio + DeepSeek：单主循环、Skills、模型协议、上下文与预算 |
| ToolExecutor | Pydantic：参数、前置条件、身份、来源、调度、超时和错误 |
| Domain / Adapters | 内容、地点、报价、路线和行程校验；fixtures/真实服务可替换 |
| Persistence | PostgreSQL：会话、任务、证据、计划版本、幂等与事务 |
| Eval / Trace | pytest、执行记录、状态快照、故障注入、归因与性能实验 |

先用关键词和结构化过滤。Redis、消息队列、向量库或额外 Agent 框架按实际瓶颈再引入。受限规划边界见 [02](02-Agent架构与实现设计.md)，MCP、混合检索和运营侧的扩展条件见 [04](04-开发任务计划.md)。
