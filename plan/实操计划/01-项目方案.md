# 01 项目方案

## 1. 一句话目标

做一个京都 2–3 天的旅行规划 Agent：模型负责理解需求、调用工具、提出方案；代码负责守住事实、约束和预订这类有副作用的操作；用评测和 Trace 证明它可靠。

**完成标准**：
- 一条 5 分钟能演示完的完整链路：从攻略进入 → 比较酒店 → 生成行程 → 只改其中一天 → 确认 → 模拟预订。演示中注入一次供应商故障，系统要能正确处理。
- 一份评测报告：DeepSeek 与 Claude 的完成率、工具调用准确率和成本对比，并附失败用例分析。

## 2. 项目定位

这是三个作品项目中的主项目，重点证明 **Agent 能力**：
- 把模糊需求变成可执行的任务；
- 管理工具、上下文和状态；
- 失败时能定位原因、恢复任务；
- 用评测证明改进是真的。

另外两个项目各自负责其他能力，本项目**不重复做**：
- **后端项目**：数据库事务、任务队列、并发竞争、压测。本项目只做 Agent 特有的可靠性（见 02 §6）。
- **RAG 项目**：文档切分、向量检索、召回评测。本项目的「搜攻略」只是 Agent 的一个普通工具，用关键词加过滤就够了。

## 3. 范围

**第一版做**：京都一个城市，2–3 天，中文对话。可以比较酒店并模拟预订（假供应商，不真实下单、不收钱）。

**第一版不做**：航班、跨城联程、真实下单、多人协作、运营后台、主动营销。

**参考来源**：
- Agent 设计参考 Anthropic 的 Commerce Agents：一个主 Agent 持有对话，工具执行和安全检查放在代码里。
- 业务场景参考 DataMind 的旅游内容推荐：用户从攻略文章出发规划行程。
- 依据见 [06](06-来源与待验证事项.md)。

## 4. 用户怎么用

一个演示用的 Next.js 网站，包含攻略文章页、规划工作台和已保存行程页。

1. **从攻略进入**：用户说「两个大人一个孩子，住两晚，不租车」。系统记住已知条件，只在查酒店需要时才追问日期、孩子年龄和房间数。
2. **比较酒店**：同样日期、人数下比较总价、早餐和退款条件。卡片上的价格由服务端填，标注来源和获取时间。
3. **生成行程**：模型排行程，代码检查时间冲突、营业时间（来自 OpenStreetMap 真实数据）和预算。查不到的信息标为「未知」，和「冲突」分开显示。
4. **局部修改**：用户说「只把第二天下午换成室内活动」，系统只改这一段，其余安排不变，并显示改了哪里。
5. **确认保存**：用户点确认后保存新版本。重复点击只会保存一次。
6. **模拟预订**：用户点「预订」后，系统先锁房（hold），再下单。假供应商可能超时或返回失败，系统不能重复下单，也不能把「状态不明」当成成功或失败。
7. **断线恢复**：刷新页面或服务重启后，能看到任务进行到哪一步，并继续执行。

## 5. 数据

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 攻略文章 | Wikivoyage 京都条目（CC BY-SA，需署名），可补少量自写 | 切成段落存库，用关键词检索 |
| 景点 | OpenStreetMap（ODbL，需署名） | 名称、坐标、类别、营业时间；营业时间直接用于行程校验 |
| 路线 | 自制路段表（步行、公交估算时间） | Google Routes 在京都的公交覆盖未确认，第一版不依赖 |
| 酒店与报价 | 明确虚构 | 个人无法接入 Booking/Agoda（需要合作方合同） |
| 预订 | 假供应商服务 | 可注入延迟、429、超时和「状态不明」 |

许可条款在入库前再核对一次。所有虚构数据在界面上标明「模拟」。

## 6. 技术组件

| 组件 | 技术 | 职责 |
| --- | --- | --- |
| Web | Next.js / React | 演示用：对话、酒店卡片、行程时间轴和改动对比、确认与预订按钮 |
| API | FastAPI | 身份、消息、确认、预订、查询；SSE 推送进度 |
| Agent Runtime | Python asyncio，手写循环 | 主循环、上下文、预算；参照 commerce-agents 的 Messages API 版本 |
| ModelProvider | Anthropic Messages 格式（DeepSeek、Claude），OpenAI 格式（对比用） | 屏蔽各家协议差异 |
| ToolExecutor | Pydantic | 参数校验、前置条件、权限、超时、错误分类 |
| Domain | Python | 旅行条件、证据、行程、局部修改、预订状态机、行程校验 |
| MCP Server | mcp 2.x | 对外提供只读工具（搜攻略、查景点）；写操作不走 MCP |
| 存储 | PostgreSQL | 会话、任务、证据、行程版本、预订、事件 |
| 可观测 | OpenTelemetry + Langfuse（自托管） | 记录每次模型调用和工具调用，提供查看界面 |
| 评测 | pytest + 自写 eval runner | 用例集、规则断言、LLM 评审、模型对比 |

不引入 Redis、消息队列、向量库或 Agent 框架。各自的理由写在 ADR 里（见 04 的 C 档）。
