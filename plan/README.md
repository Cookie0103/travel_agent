# Plaid Agent：旅游内容与旅行决策 Agent 项目计划

编写日期：2026-10-02。状态：设计完成，开发未开始。目标位置：`D:\项目\Plaid_Agent\plan`。

本项目拟以 **DeepSeek + Python Agent 内核 + Next.js/React 前端**，实现一个独立的旅游内容与旅行决策应用：游客从文章或需求出发，完成条件澄清、内容检索、地点核验、酒店比较、行程规划和保存；运营人员检查自己内容库的覆盖与质量，生成可预览、需确认的修改草稿。

业务参考 DataMind 的 Rurubu 内容推荐场景，Agent 工程参考 Anthropic Commerce Agents。项目名称是本地项目名，不表示与 PLAID、JTB、Rurubu、Booking 或 Agoda 存在合作关系。

## 已确定的选择

- 模型：POC 使用 DeepSeek；主模型、记忆提取和委派模型都显式配置。接口兼容性先验证，不默认 Commerce 的全部 Claude 功能可以直接沿用。
- 产品：独立网站；自己提供文章示例页、聊天、结果卡片、行程页和运营台。不依赖接入别人的网页才能演示。
- 城市：第一版限定日本一个城市。建议用京都做种子场景，城市配置可以替换；京都是本方案建议，尚非用户指定。
- 数据：自有或明确获授权的内容库优先；Google Places/Routes 作为可选事实补充；Booking、Agoda 作为酒店供给候选，Expedia Rapid 为后续替代。
- 两个主角色：游客 Agent 与内容运营 Agent。复杂行程的受限规划委派是进阶能力，需证明收益后启用。
- 酒店流程：查询、比较、重新确认报价、跳转。第一版不负责收款、实际下单和售后。
- 核心成果：可靠的工具执行、来源约束、结构化输出、状态与记忆、受限委派、人工确认、持久化恢复、可重复评测。

## 五个里程碑

| 阶段 | 可审查的成果 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 | DeepSeek 兼容性记录、领域契约、许可与数据清单 | 模型工具闭环跑通，复用边界明确 |
| P1 | 单 Agent 的游客端完整流程 | 测试数据模式可独立演示，来源与硬约束检查通过 |
| P2 | 检索与记忆、受限规划委派、内容运营 Agent | 对比实验说明收益；运营写入只能由授权确认触发 |
| P3 | MCP、任务恢复、外部接口适配与降级 | 断流/取消/重启/配额失败可复现并正确处理 |
| P4 | 回归评测、消融实验、展示与交付证据 | 指标报告可重跑，所有对外主张有记录支持 |

没有 OTA 凭证时，酒店流程使用自制 fixtures，并在界面和评测中标记 `fixture`。此时不能宣称已接入 Booking/Agoda 实时库存。获取合作资格与核心开发并行推进，不作为 Agent 内核完成的前置条件。
