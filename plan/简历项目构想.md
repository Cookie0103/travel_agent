# 旅游内容与行程决策 Agent｜简历项目构想

目标稿，按完成并验证的条目使用；指标待实测。[实施入口](README.md) · [掌握指南 HTML](项目掌握与AI协作.html)

**项目简介：**面向旅游内容平台的个性化推荐与出行决策场景，构建旅行助手，连接攻略阅读、酒店比较与行程规划，支持多轮条件调整、方案保存及中断恢复。

**技术栈：**Python、FastAPI、DeepSeek、Next.js/React、PostgreSQL。

1. **多轮需求与上下文管理：**针对日期、同行人和预算不断变化的问题，分离当前旅行条件与长期偏好，通过单主 Agent、按需 Skills 和上下文压缩支持连续规划，避免重复询问与沿用过期条件。
2. **工具执行与结果可信性：**针对攻略、地点与报价口径及时效不同的问题，统一工具校验、来源记录与错误处理；由服务端补全事实卡片，区分空结果、接口故障和未知信息。
3. **约束规划与架构取舍：**由模型提出行程，代码校验时间、路线和预算，并以版本化局部变更保留无关安排；在相同模型、事实与总预算下，对比单 Agent 与受限规划子 Agent，依据质量和调用代价决定是否委派。
4. **可靠执行与失败归因：**以检查点、执行版本和幂等提交处理重启、重复请求及迟到结果；关联条件变更、工具调用、证据与提交记录，区分理解、供应商和状态等错误，以原失败用例及邻近回归验证修复。
5. **效果与性能验证：**构建任务集及上下文/记忆消融，衡量完成率、事实准确性和恢复能力；在不同并发下测试排队、首反馈、端到端 P95、错误率与成本，验证供应商限流及任务积压时的有界重试、拒绝与恢复。

**30 秒介绍：**用户读完攻略，还要比较酒店、检查路线和反复改行程。这个助手把这些步骤连起来，让模型调用工具、提出方案，由后端守住事实和约束。我重点验证三件事：失败能否查清并修复，增加规划子 Agent 是否值得，以及并发和接口异常时能否保持正确状态。

实测后补两三项结果及其样本、基线和配置；委派无收益时写取舍结论。
