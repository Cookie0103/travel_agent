# v3 测评阶段性结果（2026-10-20）

本文是可以引用的结果，并说明了数据如何拼接，便于复查。方法见 [README.md](README.md)，题目格式见 [question-generation-spec.md](question-generation-spec.md)。

## 结论

在自建的 30 道多轮测评题上，每题独立运行 3 次，共 90 次真实运行，使用真实的 DeepSeek（deepseek-flash）、乐天、Google 和天气 API：

| 指标 | 结果 | 95% 置信区间（Wilson） |
|---|---|---|
| 任务成功率 | **87 / 90（96.7%）** | 90.7%–98.9% |
| 稳定通过率（同一题 3 次全过，pass^3） | **28 / 30（93.3%）** | 78.7%–98.2% |

| 类别 | 结果 |
|---|---|
| 主流程 main_flow | 11 / 12 |
| 需求澄清 ambiguous | 15 / 15 |
| 中途变更 mid_change | 13 / 15 |
| 工具故障 fault | 15 / 15 |
| 越界 out_of_scope | 9 / 9 |
| 长期记忆 memory | 18 / 18 |
| 对抗 adversarial | 6 / 6 |

未稳定通过的 2 道题，就是目前暴露出的两项弱点：
- **规划完整度**（`main-single-city-full-save`，2/3）：有一次运行最终保存的两晚行程只排了第一天上午的 2 个景点，服务端没能识别其余景点的地点证据。
- **局部修改已有草稿**（`mid-replace-one-spot`，1/3）：只有 1 次真正做到了"只改第二天下午"。另外 2 次中，一次是暂存全部报错，没改成；另一次是把整份行程重新排了一遍。两次 agent 都如实告知了用户，没有谎称已完成。

## 判定方式

- 成功与否由代码判定，依据是数据库终态和工具调用轨迹，包括：是否保存、是否下单、记忆是否落库并注入新会话的 prompt、回复是否有虚假声明、行程是否完整且没有冲突。不采用模型的自我评价。
- judge 给出的体验分**未经人工校准，不计入**上表。
- 等待时间只记录，不计入成功与否。

拼接规则：
- 每道题的 3 次结果全部取自同一次运行，用的是该题的最终版本。
- 其余 22 道题在各版本之间逐字一致（已逐行比对 git 版本核实）。
- 所有 90 次运行都没有基础设施错误。

各题为什么重跑：
1. **5 道题改了脚本，重跑一次**。改的都是脚本里缺少的用户信息，例如原脚本没说房间数、没回答"有无儿童"，agent 正确地停下来追问，脚本却没有下文。判定条件没有放宽。
   - 其中改城市、改日期、改节奏这 3 道，第一次重跑时运行器有 bug（卡片提交被服务端拒绝，对话停在第 1 轮）。修复 commit `36281fc` 之后又跑了一次，取的是这一次。
2. **3 道规划题加严了判定，重跑一次**。首轮的判定太松：两晚只排一个景点、带冲突没法保存的草稿都被判成了成功。加严后新增硬检查"每个完整游玩日至少 2 个不同景点"和"草稿没有冲突"，"只替换一处"则要求最后一轮必须提交修改。
   - 重跑时把测评自设的 Google、乐天每日上限调高了。首轮全量 90 次共用一个临时库，后半段触发了自设上限（对话里能看到"额度已用完"）。

## 人工改判（唯一一处）

`mid-replace-one-spot` 由代码判定是 3/3，看过对话后改判为 1/3：
- trial 1：最后一轮 3 次 `stage_plan_change` 全部报错，回复也说"这次没改成功"。现有检查只看是否调用、不看结果，所以漏掉了。
- trial 3：回复中承认"并不是在原草稿上只改第二天下午"，实际是整份重排。

如果不做这次改判，成绩是 89/90 和 29/30。我们采用更严格的人工结果。这个检查的不足已经记为待修：应当改为"该轮 `stage_plan_change` 成功，且是基于原草稿的补丁"。

## 使用时的限定（写进报告或简历时请保留）

- 这个结果是**本系统**（模型 + 服务端校验与状态机）在**自建 30 题**上的完成度，不代表模型的通用能力，也不能和其他 Agent 横向比较（没有对照组）。
- 测评集是按照本系统的设计编写的。其中越界和对抗题共 5 道，题型相对简单。
- 模拟用户按脚本行动。场景只覆盖日本国内、2026 年 12 月的行程。
- 测评期间同一批题目经过修改，**没有留出集**。用一批全新的题测试，成绩可能会更低。
- 行程中的"未知"项（路线耗时、营业时间、其他费用）在首轮全量中有一部分来自测评自设配额耗尽，不能作为"数据源缺失"的证据。

## 费用

四次运行合计 42.33 元：首轮全量 21.33 元，三次重跑分别为 6.93、3.85、10.21 元。最终结果所用的 90 次运行，单次中位数约 0.2 元；完整规划类题约 1.1 元一次。
