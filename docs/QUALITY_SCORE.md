# 能力质量与验收缺口

这不是任务进度副本或主观百分制。实时任务/提交/命令结果唯一来源：[执行计划](execution/travel-agent.md)。
等级：A=代码、相关失败测试和场景证据经过独立复核；B=已实现验证但部分验收缺失；待验=尚无足够证据。
等级只针对列明的能力范围，测试数与通过率不代表模型质量或生产可用。

| 能力范围 | 等级 | 证据与尚缺什么 |
| --- | --- | --- |
| 静态类型/分层/格式 | A | dev check与提交钩子；远端CI仅配置，未声称运行 |
| SDK工具/预算/进程边界 | A | M0独立复核、真实SDK离线与小样本live；不同供应商对比待验 |
| 身份/条件/Evidence隔离 | A | 真实PG竞争/回滚/归属测试，M1.1–M1.3独立复核 |
| 消息/取消/SSE持久读取 | A | M1.4复核、真实HTTP烟测、应用重建读取证据 |
| 酒店刷新/同口径比较 | A | M1.5领域/真实PG/真实SDK本地往返、6.1-sol high独立复核；范围限后端模拟报价，前端未验 |
| 行程校验/修改/确认 | 待验 | 对应M1.6–M1.9完整场景仍未交付 |
| 预订/对账/崩溃恢复 | 待验 | M2故障矩阵须真实PG与模拟供应商证明 |
| 前端与可用性 | 待验 | 尚缺类型/构建、真实浏览器完整流程与失败恢复 |
| Trace与模型评测 | B | 本地Trace/规则评测已有；Langfuse页面、完整冻结集、多次统计与人工校准缺失 |

新增能力在证据形成后更新本表，不预填分数。模型替身只证明工程链路，不能计为真实模型效果。
重大问题和技术债需注明影响范围、下一步验证和task/ADR链接；修复通过后保留原失败证据。
每个功能增量按实际变更运行专项；完整dev check/test在保存关卡执行一次，正常Git钩子按仓库要求再执行。
