# ADR-033 酒店评测世界的数据来源

日期：2026-11-28
状态：合成夹具随代码分发；已生成本机内部评测快照

## 来源

- 车站取 Wikidata P625，保留每条记录的公开实体链接。精度用于评测位置分的近似距离。[Wikidata 结构化数据许可](https://www.wikidata.org/wiki/Wikidata:Copyright)
- 合成夹具固定种子 20261127，覆盖京都、大阪、奈良、东京、札幌、福冈，每城 16 家自造酒店。每家有三种日期需求、一人及两人的合成含税房价和完整属性。
- 普通酒店模拟佣金为 8%–12%。每城第 1、5、9、13 家设为模拟合作酒店，比例 25%，同样的基准加 3 个百分点。佣金表与可展示的酒店数据分开；合作语义属于评测。
- 乐天空室接口用于用户确认的本机评估。2026-11-28 已执行一次采样，36 次查询：六城 × 三个入住档（12 月 8 日、12 月 12 日、12 月 29 日）× 一人/两人一间。使用共享调用账本、实际间隔至少 1.1 秒，按官方接口的设施结果第一页采样。定位只复用车站坐标。[乐天空室接口](https://webservice.rakuten.co.jp/documentation/vacant-hotel-search) · [乐天 Web 服务规约](https://webservice.rakuten.co.jp/guide/rule)
- 每城选 20 家，按逐日期和人数的覆盖平衡选择。六档各有 12–20 家已知报价。选每档实际报出的较低可用房价并保留该档早餐状态。缺档保存空值，反映样本未观测到报价。保存的金额来自接口的当晚报价及计价单位。

## 使用

仓库的合成文件继续供默认离线联调。真实采样存放于主工作区的 Git 忽略目录 `.cache/phase2/rakuten-private-v1/`，只保留评测所需的报价和酒店字段。采样期间每档保存局部证据，临时失败也保留已消费的次数。快照和模拟佣金文件均有 SHA-256，组装后以独立加载核对；`uv run python scripts/dev.py capture-phase2-hotels --assemble` 可从现存记录重新组装。分支只记录调用数、覆盖率及验证结论。
