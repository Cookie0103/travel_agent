## M0.1 项目骨架 + 上游代码

- **目标**：能用 `scripts/dev.py` 的 `setup`、`check`、`test` 三个命令跑通的空项目，且在 Windows 原生 PowerShell 下可用。
- **产出**：
  - `pyproject.toml`、`uv.lock`、`scripts/dev.py`（命令见 docs/execution/standards.md §4）、`.gitattributes`（`* text=auto eol=lf`）、`.env.example`、`.pre-commit-config.yaml`、`docker-compose.yml`（只含 PostgreSQL）
  - 目录骨架（按 02 §10），每个包有 `__init__.py` 和 `README.md`
  - import-linter 配置（docs/execution/standards.md §3.1 的三条分层规则）
  - `scripts/fetch_upstream.py`：把两个上游仓库 clone 到 `vendor/` 并 checkout 到 06 §2 的固定 commit；已存在则跳过。commerce-agents 拉取失败则报错退出；**DataMind 拉取失败（无权限或无网络）只打印警告并继续**，M0.6 之前不需要它
  - 一个 smoke 测试
- **验收**：
  ```bash
  uv run python scripts/fetch_upstream.py
  git -C vendor/commerce-agents rev-parse HEAD      # = fd4d592...
  uv run python scripts/dev.py setup
  uv run python scripts/dev.py check                # 退出码 0
  uv run python scripts/dev.py test                 # 退出码 0
  git status --porcelain vendor/ .env               # 无输出（已忽略）
  ```
- **理解问题方向**：分层规则在防什么；为什么 vendor 不能提交。

## M0.2 Claude Agent SDK + DeepSeek 接入验证

- **目标**：验证 Windows 上 SDK 能否在明确工具/费用限制下使用 DeepSeek 兼容线路；不再把穷举 Messages 字段作为 SDK 的替代验收。
- **输入**：旧 [协议记录](../protocols/protocol-deepseek.md)、commerce-agents 的 SDK 实现、02 §4.2 / §8.2；旧两请求授权已用完，本轮按执行计划的新整体授权执行，不逐次重新询问。
- **产出**：
  - SDK / 实际 CLI / MCP 版本与 Windows 依赖记录；uv 更新锁文件，不手改锁文件。
  - `backend/providers/sdk_probe/` 的一次性接入探针；`tests/live/test_agent_sdk_integration.py` 显式标 live。
  - 离线脚本化 SDK 消息、受控假进程/传输测试；`docs/protocols/protocol-agent-sdk.md` 区分来源、观察与未知。
  - 仅注册一个合成只读工具，核实内置工具关闭和身份/配置隔离；此处不实现真实旅行业务。
- **先离线验证**：缺 key/非法模型/预算不足拒绝启动；无 CLI、子进程退出、工具 schema 错误、失败结果、取消、轮次上限、未知 usage 均可判定，不泄露凭据。验证没有从本机账号或 fallback 走到另一收费线路。
- **live 前提**：明确供应商、模型、最大真实请求数和费用；核实 SDK 内部重试/压缩/辅助请求也可计数和限制。max_turns 不是请求计数，max_budget_usd 不是 CNY 预算。无法保证上限时停止在离线阶段并写明原因，不为了过关自动增加调用。
- **live 验收**：SDK → DeepSeek → 合成工具 → 工具结果 → 最终回答；记录脱敏事件、实际模型、SDK/CLI 版本、usage 和原币种估计。禁用 SDK 隐式重试；主 agent 定位并修复后可在剩余额度内重新验收，不盲目重复失败请求。未覆盖的续接或流式情形保持“未验证”。
- **命令**（live 仅在授权与保护就绪后运行）：
  ```text
  uv run python scripts/dev.py check
  uv run python scripts/dev.py test
  uv run --env-file .env python -m pytest -m live tests/live/test_agent_sdk_integration.py -v
  ```
- **完成条件**：离线检查通过且受限 SDK 真实往返通过；记录仍未验证的能力。旧 `test_deepseek_protocol.py` 保留历史用途，不重复运行来代替新关卡。兼容失败不自动切换 runtime 或收费来源。

## M0.3 SDK 适配、会话引用与应用事件契约

- **目标**：把 SDK 集成收敛为薄边界；应用持有旅行状态，SDK 持有模型会话，不再造通用 Message ↔ 多家模型转换器。
- **依赖**：新版 M0.2 所需技术验证与独立审查通过；无需合并 main。
- **产出**：
  - `backend/providers/claude_agent/`：配置、启动、取消、恢复、错误映射与应用事件转换。
  - 应用执行接口与会话引用：业务 session/run/user、SDK session_id、runtime/CLI 版本、供应商、模型；SDK 原始类不出边界。
  - `backend/mcp/` 的进程内工具桥接，调用已注入的业务执行入口；M0.4 再接实际旅行工具。
  - FakeRuntime / 脚本化 SDK 消息测试；在 import-linter 加入 claude_agent_sdk，保持其他层禁止直接引用。
- **验收**：正常/错误/取消/限次事件；两个用户不串会话；未知会话拒绝恢复；半条流不当成功；切换模型创建新会话；未知工具不执行。R01 / R02 对 SDK 边界的断言覆盖，不手工补造 SDK transcript。
- **限制**：这里只定义和测试恢复接口，不宣称跨进程业务恢复完成；后者是 M2.4。Claude 未实测则标记未实测，不要求开发者为此先购买所有厂商 key。
- **命令**：dev check + dev test；默认全离线。

## M0.4 旅行工具 + SDK CLI 薄片

- **目标**：问「京都有哪些室内景点」，通过 SDK 调用自写工具并给出有来源的回答。
- **产出**：约 20 个景点、12 段攻略 fixtures；`search_places`、`search_content` 的 schema、handlers 与最小 ToolExecutor；进程内 MCP 注册；`python -m backend.cli`。
- **默认行为**：CLI 与测试默认 FakeRuntime；真实运行必须显式 `--live` 并检查调用授权/预算，不因 .env 有 key 自动联网。
- **验收**：正常往返、无结果、参数错误、未知工具、下游失败、SDK 超时/限次/取消；提示词诱导不能启用文件/Shell 工具。FakeRuntime 验证业务，不冒充 SDK 内部测试或模型效果。R01 / R02 保护边界。
- **授权 live 命令**：`uv run --env-file .env python -m backend.cli --live "京都有哪些室内景点？"`；调用两个真实实现的只读工具，记录出处和结束状态。
- **不做**：不另写通用模型循环、不接真实预订、不提前实现 M1 的全部规划校验。

## M0.5 OpenTelemetry + Langfuse

- **目标**：一次 CLI 运行在 Langfuse 里看到完整 trace（02 §8.1 的 span 结构）。
- **产出**：`docker-compose.langfuse.yml`（或按 ADR-000 改用 Cloud）；tracing 初始化模块；SDK 执行、工具调用各一个 span；有证据时细分模型子调用。
- **验收**：运行 M0.4 的 CLI 后，Langfuse 中能看到 1 个 trace，含 SDK 执行信息（token、实际模型名及观测缺口）和工具 span（参数摘要、状态）；不伪造不可见的模型子调用。贴截图或 trace 链接。
- **注意**：span 中不得出现密钥和完整 prompt（docs/execution/standards.md §5）。

## M0.6 评测骨架：导入 DataMind 21 条

- **目标**：`dev eval-dev` 能跑出结果表。
- **产出**：
  - `eval/cases/datamind_adapted.jsonl`：按 05 §1.1 改编（工具名映射、三类处理），每条保留原 `id` 并注明来源；
  - `eval/run.py`：读取用例 → 跑 Agent → 规则评分 → 输出表格和 JSON 结果；
  - 规则评分器：工具选择、无多余工具、是否有结果、超范围处理（参考 `vendor/datamind-ai-agent/agent-loop/claude-managed/eval/src/graders/code/` 的思路，用 Python 重写）。
- **验收**：`dev eval-dev` 输出 21 行结果 + 通过率；`dev eval-dev --live` 经授权后通过 SDK 用 DeepSeek 跑一次，结果存为 baseline；未授权只做离线评测，不把替身输出当模型效果。

## M0.7 角色规格 + 语气评测

- **目标**：05 §3.1 的语气评测能运行并完成一次人工校准。
- **产出**：`backend/agent/persona.md`（角色规格，必须做 / 禁止做 / 长度）；对应的规则评分器；LLM 评审（0–5 分，每档有标准和示例）；`eval/calibration/` 存人工打分。
- **验收**：对 20 条回答，LLM 评审与人工打分「相差 ≤1 分」的比例写进 `docs/journal.md`；比例过低时记录改了评分标准的哪里。
- **继续规则**：先生成中性、可配置草案和评分设施，继续其他任务；用户最终确定人格并做人工校准，agent 不冒充人工完成。
