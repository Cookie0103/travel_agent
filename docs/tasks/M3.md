# M3 上下文、偏好与对照：可执行规格

依据plan/02 §5/8、03 §4、04 M3及05 R13–R17/R19。继续现有SDK与业务入口，不另建runtime、记忆框架或工具实现。

## M3.1 SDK上下文

- 每轮从PG读取当前TravelRequest、有效Evidence、plan/draft/booking指针与有界历史；历史不覆盖当前条件。SDK压缩/消息配对交给SDK，禁止改写transcript。
- 核对锁定SDK/CLI公共能力；使用真实CLI与本地模型脚本检查长历史、Skill/工具结果配对、当前条件与过期引用。实际自动压缩事件与模型压缩质量分别记录，没有触发的压缩不能声称验证过。
- 快照或偏好读取失败安全报错；中途条件变化仍由业务revision守门。补R13正常、旧事实、长文本、依赖故障。

## M3.2 用户偏好

- GET/PATCH/DELETE /preferences只作用于认证用户，不接受user_id。复用旅行字段类型，首版只保存interests、soft_constraints、transport；日期/人数/硬预算不作为长期偏好自动继承。
- 只经用户明确的偏好编辑API写入；不给模型/攻略任何偏好写工具。PATCH检查expected_revision并保留未改字段，DELETE清空且递增持久版本；重复清空无额外变化。删除墓碑版本不能重置或从旧SDK历史复活。
- 当前旅行条件优先；偏好只作为低优先级参考，不偷偷修改TravelRequest。偏好版本参与SDKcheckpoint核对；修改/删除后新会话重新注入当前事实，不续用旧记忆。
- 网页有查看/编辑/清除入口。真实PG验证两用户隔离、竞争/非法字段/回滚、删除后新轮不复活；加入工具文本注入对照与浏览器流程。

## M3.3 外部只读MCP

- 独立Streamable HTTP服务仅开放plan/03标“是”的search_content/get_article/search_places/get_place_facts。SDK内部桥接与外部协议服务分开，schema/handlers/错误码共享；不注册状态修改、酒店/预订或确认工具。
- 复用演示Bearer认证，并绑定本人已创建session；身份不来自工具参数。使用官方MCP SDK协议实现，不手写JSON-RPC；网络入口仅本机、校验Origin/Host、不扩大公开访问。
- 实际MCP客户端初始化/list/call与直接调用对照；正常/空/坏参数/未知工具/无效身份/跨用户/DB不可用均验证。工具生成Evidence元数据是读事实的应用附带行为，不修改旅行条件或执行订单。

## M3.4/3.5 对照实验

- 补数据库业务评测环境，CLI/API/评测共享TravelToolExecutor，不能以SearchExecutor的业务缺失假称模型失败或通过。
- 固定流程与自主工具选择使用同模型/数据/任务；分别标脚本测试与实际模型实验。记录完成率、工具数、真实HTTP/token/时延与原币种费用，未采集字段unknown。
- Claude线路需独立凭据/授权；可完成共用配置与报告代码，但未测不计结果，不挪DeepSeek人民币预算。不得为对比引入第二套runtime。

## M3.6 坏例与质量

- 至少3个实际dev失败保留Trace、输入/业务事实证据、根因、修复commit及原例/邻近正常例回归。5类单根因注入与正常对照只验证归因流程；证据不足标unknown，不按错误码强猜根因。
- 记录实际尝试的无效优化及回退依据，不编造失败故事。保持原用例期待，不改断言/跳过失败来制造提升。
- check/test、生成契约、web type/lint/test/build与独立审查通过后本地提交；剩余外部/模型/人工证据仍公开列待办，自动进入M4。
