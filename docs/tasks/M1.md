# M1 业务闭环：可执行规格

依据 plan/02 的调用链/状态边界、03 的对象/工具、05 的 R01–R08；任务依赖仍见 plan/04。
按自主工作流逐增量实现、真实验证、独立审查和本地提交，不等人工合并。仅使用模拟酒店/预订。
共用现有 Agent / SDK 边界、ToolDefinition / ToolResult、错误码、费用守卫和 Trace；不增加第二套循环。

## M1.1 FastAPI、PostgreSQL、迁移与 CI

- 输入：ADR-000 既定 FastAPI / SQLAlchemy2 async / psycopg3 / Alembic；已有 PostgreSQL17 Compose。
- 产出：应用工厂、健康检查、本地演示身份入口、会话创建/读取；用户与会话表；数据库配置/事务依赖；初始迁移；CI。
- 身份：服务端创建测试用户/令牌，服务端从令牌解析 user_id；客户端不能传任意 user_id 冒充。令牌不进日志，演示身份不宣称生产认证。
- API 只调用 services/agent；services 组合仓储，ORM 和 SQL 留 persistence。不为每张表生成 BaseRepository 或 CRUD 框架。
- 验收：干净的独立 Docker PostgreSQL17 测试数据库 upgrade head；重复迁移幂等；真实 API 创建/读取会话；两用户跨读404；缺失/非法身份拒绝；数据库不可用时明确失败。
- 本地开发数据库只使用项目Compose；测试只用明确测试库名，禁止drop用户数据库。默认开发端口若冲突可选本地空闲端口并记录，不覆盖已安装服务。
- 命令：dev db-up；dev db-migrate；dev check；dev test（含真实数据库集成测试）。CI用服务容器，静态/离线不加载模型密钥。

## M1.2 真实快照导入

- 产出：Wikivoyage 段落与 OSM 京都地点小快照、版本/获取时间/署名/许可；幂等导入脚本与数据库读取。
- 导入前核对官方许可；运行/评测只读已导入快照，不在线抓数据。保留人工fixture，不混成实时事实。
- 营业时间只解析支持的常见子集，复杂表达/缺字段明确unknown；不猜成全天开放。路线仍为标注估算的自制表。
- 验收：重复导入无重复实体；来源可追溯；名称/别名/城市过滤；闭馆与跨午夜样本；未知营业时间不会判营业。外部获取失败保留阻塞，不造假来源。

## M1.3 TravelRequest、RequestPatch、Evidence（自动质量关卡）

- 产出：带revision的旅行条件、set/clear patch、按用户/会话关联的Evidence；对象契约、仓储和服务。
- 条件不完整可以查攻略；酒店需要准确日期/人数/儿童年龄/房间数。金额Decimal/JPY，时间带时区。
- 条件更新在事务内检查expected_revision；无变更/解释不增加revision。Evidence绑定适用request_revision。日期/人数/房间变化让对应报价失效；交通或出发时间变更让路段失效。
- 验收R04/R05：未写字段保留、clear、版本冲突、过期/伪造/他人/同用户旧revision或日期不符Evidence拒绝补卡、缺来源字段unknown；真实PostgreSQL证明状态与失效原子更新。

## M1.4 旅行执行器、守门、Skills

- 产出：在现有工具接口上接服务的Travel ToolExecutor；schema来源唯一；受控load_skill；按run计工具/修复次数；条件和Evidence检查。
- 服务端注入身份与run；未知工具/额外身份字段/版本冲突/证据不符返回统一错误。写工具排他，只读工具有界；Skill不授予权限。
- 只注册plan/03工具，不注册正式保存/下单。复用SDK MCP桥接，按工具类型选择路由，不造插件体系。
- 同时接入基础TaskRun/消息client_message_id去重/持久化应用事件、同会话单执行者、状态读取与取消API，供M1.8的SSE使用；这些事件只需按序读取，跨进程恢复与断线补发故障验收仍在M2，不造队列系统。
- 验收R01/R03/R15/R16：参数错误不执行；并发读取受限；状态写入与读取不交错；注入文本不扩大工具权限；确认不能靠模型声明。

## M1.5 酒店查询与比较

- 产出：6家虚构酒店/至少12种报价组合，search/refresh工具，服务端同口径比较，presentation按ID补齐卡片。
- 日期/入住人数/房间数/税费一致才比总价；早餐退款差异单列。缺税不称最便宜，缺成本不判预算满足；旧报价要刷新。
- 验收：缺儿童年龄、日期变化、过期报价、币种/税费不匹配、空结果/不可用；卡片伪造ID拒绝不静默丢弃。

## M1.6 validator与反思循环（自动质量关卡）

- 产出：纯领域校验器，verified/unknown/conflict；validate_itinerary工具；SDK接收具体冲突后自行修正，最多3轮。
- 检查日期/时区、停留与路段时间、营业时间、预算、重复安排；真实未知与硬冲突分开，不放宽硬条件。
- 验收R06：闭馆、缺税、跨午夜、路线失败；脚本化SDK测试反馈/修正/达到上限；live小样本仅在剩余额度内，不为收尾多调一次模型。

## M1.7 PlanPatch、草稿与确认（自动质量关卡）

- 产出：稳定item_id的增改删、锁定项、草稿/差异/校验报告；独立确认API保存正式版本。
- 草稿归属/有效期/base_version/request_revision与写入同事务检查；用户+草稿幂等；确认前重新校验。
- 验收R07/R08：只改第二天下午不动其余项；重复地点不同item保留；锁定项拒绝；旧版本冲突；重复/并发确认只增加一个版本并返回第一次同一结果。硬conflict拒绝且数据库不变，unknown可保存但保留警告。必须真实数据库测试。

## M1.8 工作台前端

- 产出：Next.js App Router页面、攻略入口、聊天/进度、报价和行程卡片、差异与确认按钮；SSE展示已持久化应用事件。
- 默认演示模式无付费；实时模型必须显式选择且服务端检查授权/预算。表明fixture/snapshot、估算、未知、历史报价。
- 验收：前端类型/构建；浏览器实际完成比较→规划→局部修改→确认；非法/过期/版本冲突可见且可恢复，不能只截图静态mock页面。
