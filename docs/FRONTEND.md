# 前端实施与验收约定

范围：[M1.8规格](tasks/M1.md)、[plan/02 API](../plan/实操计划/02-Agent架构与实现设计.md)。前端工作区apps/web，当前是否可运行看[执行计划](execution/travel-agent.md)。

- 一个工作台完成条件查看、聊天进度、报价比较、行程差异与确认；模块按真实职责拆分。
- 复用现有组件、接口契约和请求处理；后端负责价格/证据/比较/保存校验，前端显示结果与操作。
- 每条消息生成client_message_id，网络重试保留原ID；用户新消息才生成新ID。
- SSE按已保存事件的序号展示，重连只补读；失败/取消/未知结果不能显示为成功。
- 金额从后端Decimal字符串格式化，不用浮点数重新计算报价或预算结论。
- 清楚显示模拟价格、快照版本、估算与未知；不把历史价格包装成当前可预订价格。
- 取消执行、确认保存、确认预订具有不同入口与状态；等待时防重复点击，同时由后端保证幂等。
- 表单验证、空数据、失效报价、版本冲突、网络失败都给出可执行的下一步。
- 用户文本/攻略/模型输出按文本渲染，不执行原始HTML；浏览器不接触供应商密钥。
- 使用语义控件、键盘可操作、可见焦点、明确字段标签；桌面与窄屏可使用。
- 验收包含类型/构建及真实浏览器完整操作，并覆盖至少一条失败恢复路径；静态截图不等于流程通过。

新增前端依赖先写[ADR](adr/)，必要契约只定义一次；类型检查/构建命令实现后接入开发入口及CI。
验收证据统一放evidence，结果更新[质量记录](QUALITY_SCORE.md)，不新增逐页面人工批准。
