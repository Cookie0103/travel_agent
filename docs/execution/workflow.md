# 长程执行工作流

2026-10-03 用户要求取代旧“每个任务完成后由用户审阅合并”的流程。人负责目标与最终验收，agent 负责持续实现、验证、审查和修复。质量关卡保留，人工阶段停顿取消。

## 执行与版本

1. 从现有已提交 SDK 设计继续，当前分支 batch/2026-10-03-travel-autonomous，起点 1d75f79。不回退到尚无工程增量的 main。
2. 依 04 的顺序拆可验证增量；新 M 规格若缺失，按当前 plan 补写输入、产出、失败路径、验收命令，独立检查设计一致性后直接实施。
3. 每个可验证功能增量运行 dev check、dev test 和相关专项检查；自审并经独立审查、修复后普通本地 commit，消息用任务 ID。相关的小修复可以合为一个功能增量，不为单个文件反复开审查。保留可回退提交，不改历史。
4. 独立 agent 审查给定基线/目标提交（或明确未提交 diff）、任务要求和验证证据；原七个架构关卡、大里程碑和最终交付还需深入核对跨模块不变量。审查记录发现、位置、风险、修复及复核结果。
5. 重大正确性、安全或数据一致性问题必须修复后才能进入依赖工作；一般问题记录和排期。自审与独立审查都不能替代测试。审查通过即自动继续，无需用户点击或合并。
6. 普通失败先诊断再修复；同一根因三次有针对性的尝试仍无新信息时换验证方法或转做独立任务。保留工作，不机械因两次检查失败就停整批，不为通过而删断言。

## 状态与证据

- plan/04 定义任务和依赖；docs/execution/travel-agent.md 是唯一实时执行状态，不维护两份完成清单。
- 标记 todo / in_progress / verified / blocked，并分别说明“代码完成、离线验证、真实验证、独立审查”。四者不能混为一谈。
- SDK 实测欠缺时，不将替身当真实 runtime；可以继续与未知 SDK 行为隔离的业务代码，不把不确定语义固化为下游公共接口。
- 没有 Claude 凭据、预算不足、待人工角色校准等只影响相应验收；保留待办，推进其他工作。所有必需标准未满足时不能声称项目“全部通过”。
- 工作进度和决定及时追加；记录命令及真实摘要、验证产物、恢复点，不记录密钥、原始推理或内部仓库原文。

## 自主决策与用户边界

可自主：既定架构内拆包、兼容修复、测试、迁移/fixture、端口选择、先写 ADR 后安装必要依赖、离线替身、可回退 UI 默认值；记录方案与替代项。
角色先用中性“旅行助手”草案实现配置与评分设施，等待最终选择；agent 不冒充用户已定人设，机器评分不冒充人工校准。
需用户：新增凭据、扩大模型花费或供应商、不可逆发布/付款/外部写操作、改变 SDK 路线/业务安全边界、扩大 C 档范围。
对 SDK 的兼容问题先研究并验证；无证据不得更换 runtime 或偷偷调用美元线路。自动审批拦截时记录原因，先做允许的部分。

## 最终集中交付

交付可运行应用、启动命令、演示步骤、验证/独立审查结果、费用与未完成项。按入口、状态、工具、失败恢复和评测组织一份学习索引，再由用户运行和复述，整理真实面试故事。
保留历史 docs/review 与批次记录；新记录按完整里程碑汇总。学习与最终人工架构审阅不作为 agent 开发期间的前置门槛。

## 中断恢复

每次结束当前执行片段前写当前提交/工作区、正在执行的命令、下一步、阻塞项和累计用量。恢复时核对进程与 Git，不能重复扣次数，也不能从日志“开始”推断命令成功。
电脑关闭/睡眠、网络不可用或 Codex 运行限制会暂停计算；文档能支持续接，不能替代运行中的执行环境。不改系统睡眠设置，不自行申请 Full Access。
