## 每个案例需要的素材（完成后按 STAR 改写）

### C1 会话隔离与历史恢复
- S：用户从京都改成札幌，右侧仍是京都行程；刷新后对话只剩最后一条回复。
- T：一次旅行 = 一个 session；数据库是业务真相，localStorage 只是缓存。
- A 待补：定位过程（单 key localStorage、单 run 渲染、确认后清 run_id）→ 为什么新增两个只读接口而不是本地存历史（ADR-014）→ 迟到 SSE 如何丢弃 → 测试。
- 可能追问：为什么不用 localStorage 存全部历史？多标签同时操作怎么办？分页为什么有界？旧前端兼容吗？

### C2 Agent 成功与业务提交分离
- S：草稿生成失败，回复却说“已通过多轮校验”。
- T：状态由服务端业务结果决定，不由模型文字决定。
- A 待补：run 状态来源（runtime outcome）与草稿 ValidationReport 无关联的证据 → 业务结果字段设计 → 确认幂等（按 draft_id）与读回失败处理 → 测试。
- 可能追问：为什么不靠提示词约束？conflict 和 partial 的区别与是否允许保存？双击确认如何保证只一个版本？

### C3 no-op 更新也加版本
- S：不改任何可见字段，保存后条件版本 3→4。
- T：无语义变化不增 revision、不使草稿失效。
- A 待补：前端 mergePace 追加 + 回退默认值整表提交、后端逐字段比较 → 先红测试 → diff 提交 → 结果。
- 可能追问：为什么前后端都要处理？revision 增加的副作用是什么（草稿/卡片失效）？

### C4 酒店推荐与可信报价
- S：要 4 家返回 4 个选项但只有 3 家；“查看酒店”直接跳到预订页；6 万全程预算被当作每晚。
- A 待补：报价 key 是 hotel/plan/room，截断发生在报价层 → 按 hotelNo 分组；URL 三分；预算字段拆分（ADR-015）。
- 可能追问：为什么不按最低价排序？价格未知为什么不能填 0？如何控制供应商调用量？

### C5 安全发布

- A 待补：D1 的处理、一个功能一个 commit、兼容迁移、回退演练记录。

## C6 可复现依赖策略（完成）

- S：普通 uv 命令在运行检查前重新解析；用户全局相对“7 days”策略随日期变化，项目锁文件没有该策略。
- T：在项目内固定解析策略，不改用户全局配置、不升级锁定包，正常 uv run 可执行。
- A：先用临时用户配置2000-01-01与真实 uv lock --check --offline 写回归，1 failed；尝试 exclude-newer=false 被安装版本拒绝，保留失败记录。采用项目 RFC3339 固定截止与工具生成的 lock 元数据；补 Windows APPDATA 注入，独立复核通过。
- R：修复提交 `3771886` 已 push；专项1 passed/0.08s，普通 dev check通过249文件/3契约/10文档入口；包版本/制品未变。全量基线另有7项SDK失败，不能把本问题解决当全项目通过。证据：[P-03](../../plans/2026-10-08-product-v2.md#p-03-d4-用户全局-uv-日期策略触发重新解析)、[原过程](../../operations/product-v2.md#2026-10-08-t01-uv-配置复现与修复)。

深挖问答：
1. 锁文件为何仍受影响？解析选项与生成锁时不同会触发重解析，需同时固定项目策略与锁元数据。
2. 为何不用 --no-sync？它可临时运行已装环境，但没有解决正常同步入口。
3. 为何不关掉全局策略？它是用户其他项目的偏好，项目配置范围更小且可随仓库复现。
4. 是否验证Windows？strict win32检查通过，环境目录逻辑为文档/代码推断，未运行Windows实机，不能写成实测。
5. 是否证明dotenv发布时间导致原问题？没有；最小实验明确证明日期策略可阻挡锁定依赖，原日志还包含DNS/缓存失败，不扩写未证实因果。

## C7 共享身份与异步恢复边界（完成）

- S：旅行切换新增实现中，独立审查发现旧标签401可能误删另一标签的新身份；清空视图后的读取过程和旧API404可能被显示成“没有历史”。这是实现时发现的问题，不能归因为原线上保存事件。
- T：失败只作用于原owner；未响应消息保留原client_message_id且只在原身份/旅行明确重试；加载及版本不支持与业务空列表分开。
- A：以真实storage helper写旧owner/新shared身份回归，首红35 passed/1 failed；按原token清标签outbox、只删匹配local身份。切换设置restoring并按generation收尾；历史404显示版本提示、禁止empty。用仅本地离线wrapper注入6秒request延迟及404，实际Chrome检查，而非把helper当React竞态验收。
- R：T1.3提交/push `1786c37`；web最终37 passed/type/lint/build5路由；Chrome延迟期间仅恢复状态，旧API明确提示；京都3轮/V1保留、札幌独立1轮且PG同user，0重新登录。check252文件/3契约；完整1014 passed/原7 SDK失败保留。3项独立P2关闭。证据：[P-08](../../plans/2026-10-08-product-v2.md#p-08-计划外身份-新切换流程的归属与加载边界)、[操作](../../operations/product-v2.md#2026-10-08-t13-同身份旅行切换与临时outbox)、[脱敏结果](../../evidence/product-v2/t13-trip-isolation.json)。C1整体仍候选，卡片/全部正式列表与原事件未完成。

深挖问答：
1. 为何不能按localStorage当前token清理？它跨标签共享，当前值不一定是失败请求所属身份；必须携带原owner并比较后清理。
2. sessionStorage是否保证所有多标签问题消失？没有；它隔离临时outbox，不能替代服务端幂等与归属，测试只证明具体旧owner边界。
3. 404为何不是空历史？旧部署可能没有新增接口，应明确提示不支持；只有成功读取到items=[]才能当成业务空。
4. 是否验证真实札幌服务及全部竞态？没有；本轮固定免费脚本仍用京都样本，只验证旅行存储/轮次隔离及指定延迟场景，卡片/SSE留T1.4。
