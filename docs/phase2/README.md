# 第二阶段：评判打分与自进化

2026-11-27 起。第一阶段做出了可运行、可评测的旅行 Agent；这一阶段回答“它做得好不好、怎么让它自己变好”。

## 读的顺序

1. [设计](design.md)：五条工作线各自怎么设计。先看第 0 节的总览图。
2. [开发计划](plans/2026-11-27-judge-evolution.md)：任务表、待决定事项、每日进展、问题解决记录。**任务状态只在这里改。**
3. 需要查依据时：[调研笔记](../../archive/phase1/research/judge-scoring-notes/)（9 篇，按主题分）。
4. 规则和系统说明：[手册](../handbook/README.md)。

## 这个目录放什么

```text
phase2/
  README.md      本页
  design.md      本阶段的设计（唯一来源）
  plans/         开发计划，一个批次一份：<开始日期>-<主题>.md
  evidence/      脱敏证据：参数定参报告、评测汇总、对照实验表（开发中产生）
  operations/    命令与原始过程（开发中产生）
  evolution/     自进化每条候选修改的审核页（开发中产生）
  cases/         面试案例（对应的问题记录全部完成后再写）
```

后四个目录在第一次需要时创建，并在本页补一行说明里面的文件。

[D9 小样本复核入口](operations/small-experiments.md)记录固定样本和运行方式，[面试案例](cases/2026-11-27-judge-evolution.md)收录已有证据的案例。
