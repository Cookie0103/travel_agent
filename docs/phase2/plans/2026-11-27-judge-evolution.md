### 3.2 规则关卡怎么接

- 运行时：拦截级没过，沿用现有修复额度打回（`Limits.max_validations = 4`，即首次 + 3 轮，盘点 A6）；额度用完仍没过，按现有流程带冲突暂存并如实展示。本阶段不改“确认保存时有冲突返回 409”的行为。
- 评测时：终态仍有拦截级违规的一次运行记为“没过关”，期望分记 0；同时单独报告过关率和过关者的平均分。
- 首屏占比上限、相关性底线、合作标注三条与合作酒店有关。合作标注进产品（报价对象加“是否合作”，页面显示标注）；占比上限和相关性底线依赖下单概率，只在评测侧判。

### 3.3 Skill 候选目录

自进化和放置实验都要在不改仓库文件的前提下换一套 Skill 跑评测。做法：`TravelToolExecutor` 读 Skill 的目录可由评测配置指定，只在评测配置且连的是评测库时生效，判定方式照 `backend/adapters/evaluation_faults.py:98` 对故障注入的限制。白名单机制不变。

### 3.4 模型分工（2026-11-28 定）

| 事情 | 用什么 | 落到实现上 |

### 3.6 提交钩子怎么修（A1、A2 要做到的事）

钩子做什么：`.pre-commit-config.yaml` 在每次提交时依次跑 `dev check` 和 `dev test`。`dev check` 现在是通过的，挡住提交的是 `dev test`。它需要本机 PostgreSQL（先 `dev db-up`），整套约 7 分钟，`dev.py` 给的外层时限是 600 秒。钩子本身不改。

| 原因 | 多少条 | 怎么修 | 怎么确认 |
| --- | --- | --- | --- |
| 夹具日期过期（P-201） | 约 420 | 测试统一使用固定的“今天”。已验证可行的做法：在 `tests/conftest.py` 加一个默认生效的夹具，把 `backend/domain/travel_request.py` 里 `tokyo_today()` 读到的当前时间固定在 2026-10-10；验证时就是这样做的，结果 2465 通过。三点注意：① `TravelService.__init__` 的默认参数在导入时就绑定了 `tokyo_today` 这个函数对象，所以要固定的是函数内部读时间的地方，替换模块里的函数名不起作用；② 以子进程启动的测试入口（`tests/integration/api_process.py`、`recovery_worker.py`、`sdk_context_worker.py`）不受夹具影响，要经环境变量把固定日期传进去，并且只在测试配置下生效；③ 现有的 `fixed_today` 夹具只改了 `backend.services.travel` 里的一处，并入新的统一夹具，不留两套时钟。业务的日期校验不改 | 把固定的“今天”换成 2030-01-01 再跑一遍，日期类失败仍为 0 |
| Windows 路径分隔符 | 2 | 先确认是测试的比较写法问题，还是产品在 Windows 上输出的相对路径确实不一致；前者把断言两边统一成正斜杠，后者修产品输出 | 两条在 Windows 上通过，CI（Linux）结果不变 |
| Claude CLI 版本不在白名单 | 6 | 这 6 条是直接跑 pytest 时失败的。`dev test` 会读 `.env` 里固定的已验证 CLI，先用 `dev test --path` 复现；仍失败再按[测试总览 §4](../../handbook/testing/README.md) 处理（安装白名单版本或指定 `TRAVEL_CLAUDE_CLI`）。不改白名单，不改断言 | `dev doctor` 显示 CLI 在已验证列表；6 条通过 |
