# 自进化与评测面试案例

## 本地模型怎样从协议可用走到业务验收

**背景与任务**

第二阶段原本计划让本机模型承担大量旅行评测。在同一套 Claude Agent SDK 中，验证本机模型能否用旅行工具跑完整流程，并达到固定的草稿与耗时门槛。

**行动**

先绕开真实供应商，用合成资料复现本地流式协议。首字节等不到时分辨传输层超时和模型输出。随后发现 Ollama 首帧的输入 token 估算可能高于末帧的实测值。仅在本机线路用末帧记账，保留事件顺序、模型、上下文及工具白名单校验。记录真实工具调用，最后按预定草稿门槛验收。

**结果**

正式批次前三题均超时，没有合格草稿。10 道里最多还可能通过 7 道，已达不到 8 道门槛，停止剩余七题。按既定方案转向 DeepSeek 小样本。修复验证中完成过选条件、查酒店、显示卡片、查景点和天气的真实工具往返。[A7 实机记录](../evidence/local-agent-a7-v1.md)

**深挖问答**

- 怎么区分协议和业务成功？单次工具往返验证 SDK/模型兼容，业务验收要求按真实工具序列走到合格的草稿。
- 为什么直接停？门槛按整组固定，三道已经失败，余下七道即使全过也不足。
- 如何防止本机变更影响计费？用量兼容只落在本机配置，付费线路继续使用原验证路径。

**AI 协作边界**

Codex 定位与实现兼容改动，测试记录提供协议证据，项目的固定门槛决定是否使用本机跑量。

## 一次采样怎样支持离线定参与回放

**背景与任务**

希望用真实报价分布改进推荐公式，同时让供应商访问保持一次性，且让模型评估使用可冻结的输入。

**行动**

按六城、三个入住日期和两档人数采样，共 36 次请求；每城离线选 20 家覆盖不同档位。快照用原始请求范围和内容哈希回放，缺报价保持缺失。用独立调参与验收分别检查参数，把私有回放限制在本机评测，仓库只保存脱敏汇总、冻结参数和实现。

**结果**

快照覆盖 120 家酒店，每个采样档 12–20 家可报价。定参检查的调参与验收分别通过 102/102 和 72/72。真实报价和快照留在本机。[定参结果](../evidence/commerce-calibration-rakuten-v1.md)

**深挖问答**

- 同一酒店缺一档怎么办？保留缺失，回放不借用不同人数或不同日期的价格。
- 怎么知道参数没有只适配调参集？搜索只使用调参部分，确定一个冻结版本后才看独立验收结果。
- 外部模型实际看到什么？小样本用隔离的合成供应商世界，真实快照只供本机回放。

**AI 协作边界**

采样范围依据项目计划，Codex 执行、组织脱敏证据和复算分数，保留原始价与供应商内容的本机使用边界。

## 如何判断自进化的改动值得保留

**背景与任务**

想比较同一个旅行 Agent 的两种改法。使用相同起点和相同的 12 次候选重跑、6 次终点评测预算。留出题仅测终点。

**行动**

第一版让 Codex 看合成反思轨迹后重写一个 Skill，按反思题的弱公式判断。第二版先从代码检查找最常见失败，只改现有 Skill 的一句，在另一组验证题检查目标、回归、分量和共存。两版都将候选、配对证据和审核页放在隔离目录。

**结果**

**题库修复前，不作为结论。** 第一版反思题 5/12 → 5/12，弱公式期望分 0 → 0。第二版验证题 6/12 → 7/12，目标失败 6 → 5，未达到保留门槛。两版终点采用相同的起点 Skill，各通过 4/6，逐题有两道翻转。[两版对照](../evidence/evolution-comparison-small-v1.md)

**深挖问答**

- 期望分提高，为什么候选仍留在本机？目标闸要求失败至少减少两道并且减半，本轮只少一道。
- 两边留出题各过四道，说明模型稳定吗？总通过数相同，逐题有两处翻转，显示小样本比较需要保留配对明细。
- 如何避免在留出题上调参？反思、验证与留出冻结，留出只在终点运行，不进入反思输入。

**AI 协作边界**

Codex 提文字候选，代码判对错和商业分，人工审批决定是否合并候选。此次没有候选通过保留门槛。
