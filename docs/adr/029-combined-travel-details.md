# ADR-029：交通、节奏与时间一次确认

状态：accepted（2026-10-15，用户明确批准组合卡与统一确认）。

## 决定

复用 ChoiceCardRow 的 JSON 内容及 RunService.submit 消息事务，增加 travel_details 类型：交通、节奏各三个服务端固定选项，已知值预选；唯一提交选项为 confirm。点选只在 React 本地更新状态，用户点“确认并继续”才发一条结构化消息。在同一会话锁内校验归属、revision、卡片选项与完整答案，原子更新条件和创建消息；原 client_message_id 重放保持幂等，换答案重放拒绝。旧 pace、预算及记忆卡仍按原协议读取。

抵达/离开沿用既有 hard_constraints 文本，不增加一套日期语义或数据库表。卡片仅展示已有且含抵达/返程角色及明确时刻的完整硬条件，排除每日出发。未识别的自由文本不猜测；提示词先保存已明确的用户安排再发卡。已有时间须明确点是/不是；否时逐条展示原文编辑框，填写更正后统一提交。更正数组与原卡条数一致，每条仍最多200字，不挤成一个200字字段。更正只替换卡片完整展示的那些条件，保留其他硬条件、预算与每日出发。若一个条件含多项事实，显示整条并提示只改需更正部分，不静默截去其他事实。没有时间提议时不强制询问时间。

待确认状态跨轮保留，无关revision变化或含糊“继续”不解除门禁。文字明确回答时先经原update_travel_request记录更正，再update_conversation_state(confirm_details=true)结束上一轮卡片；服务端禁止发卡同轮代用户确认。该标志只处理交通/节奏/时间，不触及预算或记忆确认。重展新组合卡将旧未答卡作废；取消任务同事务作废其未答卡。刷新从ChoiceService按需补全卡片，未获响应的提交在标签页outbox中完整保留结构化答案与原client_message_id，需用户明确重试，不自动重放。

自动 awaiting_field=transport/pace 均返回组合卡；模型不重复列按钮或另起时间确认。该变更仅改变信息收集交互，不修改规划校验、次数/费用上限、供应商或 SDK runtime。

## 取舍

不采用单个按钮立即触发模型，也不分别提交两张同 revision 卡，避免提前规划及第二张卡因版本变化失效。不新增通用表单引擎、依赖或数据库迁移。未提交选择仅为本页面临时编辑；已确认事实与卡片回答持久化，刷新从 PG 恢复。
