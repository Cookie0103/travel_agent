# ADR-020：外部读取只在拥有请求的边界重试一次

状态：接受（2026-10-13，V2 批次；模型旧测试例外待用户答复）。

## 决定

供应商读取复用 `request_json`：429、超时、网络失败、5xx、无效 JSON 最多重试一次。400 不在适配器重试，模型只获得同一业务操作的一次参数修正机会；修正后任何失败均结束该机会。乐天只有 `404 not_found` 算空结果。每个尝试先提交 PostgreSQL 配额计数，不因请求失败退款。

429 使用 Retry-After（数字或 HTTP 日期），最多等待3秒；没有有效值时等待1秒加0到0.3秒抖动，其他瞬时失败等待0.5秒加同样抖动。剩余工具期限不足或配额耗尽时不发送第二个请求，并保留首错、实际尝试数与跳过原因。

乐天发送共用当前事件循环的锁与最小间隔；默认1.1秒是本项目保守假设，不是上游QPS承诺。可通过 `RAKUTEN_MIN_INTERVAL_SECONDS` 设置0到3秒。Google与天气没有这个节流。多事件循环隔离锁，避免测试、运维入口共享已绑定的锁。

首次瞬时失败由适配器吸收；400待修正结果保留真实错误码并标记 provisional。错误卡、活动列表和最终说明采用同一元数据。最终外部失败按规范参数缓存，缓存检查与结果更新在既有工具锁中进行，不被无关成功清空。Stop 暂停只有导致暂停的同一业务工具成功后解除；天气保持原有特例。

模型仍通过既有守卫和 SDK。拟增加首个流开始前的429/5xx一次HTTP重试，复用既有期限余量；不与HUMAN首字节停滞重试叠加，200流解析失败不重放。SDK重试继续关闭。每次单独预占；失败无可信用量时保留预占，成功用真实用量结算。不能为了满足计划里“两次都结算”的测试措辞而伪造零费用或退款。

元数据是闭合类别、HTTP数字状态、实际尝试次数、等待、首错与恢复/跳过标记。汇总 trace 保留逐次类别，不上传请求、响应正文、完整URL、供应商错误原文。事件序列化复用 TypeAdapter，使元数据可经worker、进程事件与PostgreSQL一致恢复。

## 取舍与验证

不新增重试框架、运行时、依赖或第二套计数。供应商异常注入使用 MockTransport 与真实 PostgreSQL；限速用虚拟时钟。模型重试以合成转发器证明未知费用、半条流与混合停滞边界。真实调用和最终通过数仅记录在[当前批次](../plans/2026-10-13-interaction-memory-eval.md)。

2026-10-14 F2：酒店结果闭合声明choice_card及单次查询HTTP attempts/auto_retried，超长正文被拒绝仍保留ExternalAttempt；模型不能把参数修正的第二次工具调用说成适配器自动重试。卡片无方案/已拒绝时不得请用户点卡，实际卡由服务端presentation提供。
