# ADR-021：选择卡由服务端生成，并在消息事务中确认

状态：接受（2026-10-13，V2；长期记忆按 D9 始终逐条确认）。

## 决定

选择类型是封闭的 pace、budget_relaxation、memory_confirm。模型只请求类型与当前版本，不能提供选项、身份或确认结果。选项、展示问题及绑定依据由服务端产生。

选择卡放在 choice_cards 表，归属会话，记录来源 run、条件版本、生成时间及已答选项/目标 run。复用原会话锁、client_message_id 幂等与 revision CAS；卡片、条件更新与新消息同事务。不同消息 ID 重答为409，旧版本409，未知选项422，外部会话404。相同消息ID先回放原run，已答或条件变化不触发再次执行。

节奏三个按钮显示标准、特种兵、比较轻松，最后一个的领域值为慢节奏。更新复用既有 RequestPatch 与条件来源规则，清除 hard/soft 两层旧节奏别名，保留其他条件；点选作为用户设置。模型复述同值不会降低手填来源，明确改变的会话条件仍沿用原规则。

awaiting_field=pace 时在服务端自动生成卡并推送 presentation。显式请求可修改已有节奏，生成卡时不改变原选择。反复展示同run/版本的卡复用已有ID。卡片不证明酒店比较或行程规划完成，SDK待办不被误消除。

前端复用现有按钮及useClock，不构建通用表单框架。键盘Enter可选择，忙碌/已答/过期时禁用。最新卡、恢复页和分页历史都读取PG中的回答状态；历史补卡只读取选择状态，不重新查询供应商事实。选择完成生成确定的续跑消息，不需要用户打字反馈。

pace主要通过revision失效；报价确认卡需要额外TTL，记忆卡需要偏好版本绑定。具体绑定验证由相应业务服务负责。事件仅保留选择白名单与option_id/label/value，剔除附带正文。

## 验证与回退

真实PG验证并发重放、归属、版本、未知选项、已有节奏替换及重启恢复；原生SDK/CLI以合成SSE验证自动/显式展示复用；Chrome使用真实DeepSeek确认键盘选择、续跑与刷新已选状态。实测数值只维护在[本批计划](../plans/2026-10-13-interaction-memory-eval.md)。

部署前需用户确认。回退应用代码保留新表供重新升级使用，不在生产执行删除数据的downgrade。
