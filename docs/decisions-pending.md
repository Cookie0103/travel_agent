## M0.2 开工前的配置选择

- 用户已明确决定按人民币与美元分开预算；这是用户要求，不是待决定的设计。
- 未明确给出新人民币预算数值：新增 DAILY_BUDGET_CNY=0.10 元，原 USD 非空值保留，空值设为 0（禁用）。备选是按汇率换算旧美元数值，但旧配置没有确定可换算金额，且用户要求尽量少花，因此选择较小的独立上限，不做换汇。若要调整，仅修改本地 .env 的相应预算值；本次不修改密钥或其他配置。

## M0.2 本批选择

- 用户随后自行把 CNY 设为 5.0、USD 设为 0；代码保留这些值，并继续遵守少量调用限制。
- 分支：依 §2.1 延续当前 M0.1 → M0.2 批次，因 M0.1 不是关卡；备选为另开批次，但 main 尚无 M0.1，需等用户合并。如果不同意，可只在本分支审阅，勿合并 M0.2 增量。
- 模型：用户指出缺配置后，添加 DEEPSEEK_MODEL，初始选官方明确列出的 deepseek-flash；备选 pro 的价格更高。两模型分别计价，未知模型拒绝。不同意时修改本地 .env；新增模型还须先核对 settings.py 的价表。
- 预算：本探针采用请求前持久计次与保守费用占用，不退款；备选为精确预留/结算，但超出少量实测所需，也属于后续复杂方案。不同意时审阅 ledger.py / transport.py / ADR-002；不能靠删除本地账本恢复次数。
- 实测范围：用户单独确认这一次、最多两请求后，只做一次成功最小往返；备选为全矩阵更多实测，未采用以满足节省调用的要求。完整矩阵仍有无法判断项，因此保留 M0.2 关卡，不开始 M0.3；未修改 plan/ 验收标准。

## M0.3 实施选择（2026-10-03）

- 首版只保留进程内、服务端产生的会话引用；失败后旧引用失效，跨进程恢复留给 M2.4 的真实 PostgreSQL 故障实验。备选是提前持久化 SDK 原始消息，但会重复 SDK 能力且没有事务保证，未采用。
