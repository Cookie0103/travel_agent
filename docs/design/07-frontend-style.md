## 1. 原则

- 简约：一个主色 + 灰阶，不用渐变、不用阴影（只用 1px 细边框区分层级）、不放装饰图片。
- 参考方向：对话在左、行程在右的分栏产品（如 Layla）。**只借鉴信息结构，不照抄外观**；参考页是用户登录态的私有页面，本仓库没有其截图，本文按用户的文字描述制定。
- 一屏只突出一个主操作。
- 工具选择：Tailwind CSS + shadcn/ui（组件源码复制进仓库，自己拥有；样式简约；日期选择、弹出层等无障碍行为由 Radix 提供）。新增依赖须先写 ADR（见 [AGENTS.md](../../AGENTS.md)）。

## 2. 颜色（改色只需改 token 一处）

| token | 值 | 用途 |
| --- | --- | --- |
| `--primary` | `#CDB3FF` | 主色：用户消息背景、选中态底色、主按钮底色、时间线圆点 |
| `--primary-ink` | `#1E1033` | 主色底上的文字（深紫黑） |
| `--accent` | `#7C4DDB` | 链接、焦点环、主色用在**文字或细线**时的深色版 |
| `--bg` | `#FFFFFF` | 页面与助手回复背景 |
| `--bg-subtle` | `#F8F7FB` | 右侧面板底、卡片悬停 |
| `--border` | `#E6E3EE` | 1px 边框 |
| `--text` | `#14121A` | 正文 |
| `--text-muted` | `#6B6679` | 次要文字 |
| `--success` | `#15803D` | 已保存、校验通过 |
| `--warning` | `#B45309` | 警告、未核实 |
| `--error` | `#DC2626` | 失败、冲突 |
| `--info` | `#2563EB` | 提示、数据说明 |

对比度（按 WCAG 相对亮度计算）：

- 白字放在 `#CDB3FF` 上只有约 1.8:1，**不允许**。主色底上一律用 `--primary-ink`（约 9:1）。
- 主色做文字或细线颜色时用 `--accent`（对白底约 5.3:1，达到正文 AA）。
- 语义色（对白底分别约 5.0、5.0、4.8、5.2:1，均达到正文 AA）只用于小标签、图标和文字，不做大面积底色；语义信息不能只靠颜色，必须同时有图标或文字。

## 3. 排版与间距

- 字体：系统字体栈，中日文回退 Noto Sans；不引入外部字体文件。
- 字号只用四档：14（辅助）/ 16（正文）/ 20（小标题）/ 28（页面标题）。
- 间距为 4 的倍数；圆角统一 12px（按钮、输入框可用 8px）；不用阴影。
- 不做暗色模式（本批不在范围内）。

## 4. 布局

- 宽屏：左右分栏，左对话、右行程；窄屏：对话与行程用标签切换。
- 对话区：
  - 用户消息：`--primary` 背景 + `--primary-ink` 文字，靠右，圆角气泡。
  - 助手回复：白底黑字，**不加气泡框**，只靠留白和左对齐区分；工具步骤折叠在回复下方。
  - 输入框固定底部，发送按钮用主色。
- 行程面板：竖向时间线，按时段拆开：
  - 第 N 天（日期）→ 到达/出发（航班或交通）→ 白天 → 晚上/住宿。
  - 例：第 1 天 10/17：到达 → 白天 → 晚上；第 2 天 10/18：白天 → 出发。
  - 每个片段是一张白底细边框卡片；不放视频、海报。
  - 白天/晚上的划分：设想按行程项的开始时间在前端归类（如 17:00 前为白天）。**待核实**每个行程项是否都带时间；若不是，需要先确认数据再定规则，不能凭此改后端契约。
- 酒店：横向可滑动的卡片条，**最多显示 5 家**，条末尾放“在乐天查看更多”按钮跳转乐天酒店搜索页。每张卡等宽，价格与按钮固定在卡片底部对齐。该功能的详细设计见[批次计划附录 A](../plans/2026-10-08-product-v2.md)，属于下一批，不在本文实施范围。

## 5. 状态

- 加载：骨架屏，不用转圈占满页面。
- 失败：一行 `--error` 文字 + 原因 + “重试”；原因取自固定的原因码映射，不展示任意异常文本。
- 空状态：说明现在没有什么、下一步做什么。

## 6. 迁移方式（实施时）

1. 开单独分支，先引入 Tailwind 与 token，保留现有 CSS 并存。
2. 先迁行程面板，再迁对话区、其余模块；用户已授权自主继续，每块仍须Chrome实际查看，不跳视觉验收。
3. 每迁一块，跑 web 测试、typecheck、lint、build，并在 Chrome 逐项验收；不顺手改业务逻辑。
4. 全部迁完后再删除旧 `globals.css` 中不再使用的部分。
