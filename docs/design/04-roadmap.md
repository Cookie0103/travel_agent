# 04 开发任务计划

2026-10-03：用户授权长程自主开发，取消阶段人工批准与合并关卡。本文件维护 M0–M4 共 33 项任务的定义/依赖，实时状态与证据仅见 [执行计划](../execution/travel-agent.md)。
新里程碑规格由 agent 依据既定设计补写并独立检查后执行。M0.2、M0.3、M1.3、M1.6、M1.7、M2.2、M2.4 保留为自动质量关卡：测试、自审、独立审查、修复通过后，同一开发分支直接继续，无需用户确认或合并 main。
缺外部条件时保留相应验收待办，推进可隔离工作；不能把未测标为通过。

## 0. 范围三档

| 档 | 含义 | 内容 |
| --- | --- | --- |
| **A 必交** | 做透：实现 + 测试 + 能画图讲清楚 | SDK 运行时接入、ToolExecutor 与守门、Pydantic 契约、Evidence、validator 与反思循环、PlanPatch 局部修改、确认保存幂等、模拟预订（审批 + 幂等 + 对账）、OTel + Langfuse、60 条评测（含工具调用准确率）、DeepSeek vs Claude 对比 |
| **B 最小版** | 核心路径能跑，各有一个故障测试 | 服务重启后恢复任务、SSE 断线补发、对外只读 MCP 服务、固定流程 vs 自主选工具对照、长期偏好（查看 / 删除） |
| **C 只写 ADR** | 写清「为什么现在不做、什么条件下做、怎么做」 | 受限规划子 Agent、多 worker 租约竞争、预算预留与结算、准入控制（429/503）、压测、为何选择 Agent SDK、暂不引入其他 runtime / Redis / 向量库 |

原则：A 档没做完，不开始 C 档；C 档不写代码。

## M0：SDK 接入验证 + CLI 薄片

目标：第一周就能在命令行跑通「输入 → 模型 → 工具 → 校验 → 输出」，并在 Langfuse 里看到 trace。

| ID | 任务 | 依赖 | 交付与验收 |
| --- | --- | --- | --- |
| M0.1 | 工程骨架 + 上游源码学习 | — | 保留本地工程提交和验证证据；`docs/guides/reuse.md` 补充 Messages 学机制、SDK 学接入两条阅读线 |
| M0.2 | Claude Agent SDK + DeepSeek 接入验证 | M0.1 | Windows SDK/CLI/MCP 版本、工具隔离、费用/次数边界、SDK 最小工具往返；旧探针 `3819723` 不是 SDK 验收 |
| M0.3 | SDK 适配、会话引用与应用事件契约 | M0.2 | SDK 类型局限 providers/mcp；会话隔离、取消、错误事件与 FakeRuntime 测试通过；不做跨供应商原始消息迁移 |
| M0.4 | 最小 fixtures + 2 个旅行工具 + SDK CLI 薄片 | M0.3 | 问「京都有哪些室内景点」能调用自写工具并回答；离线替身测试通过；真实验收按授权运行 |
| M0.5 | OTel + Langfuse 接入 | M0.4 | 本地 docker 起 Langfuse；一次 CLI 运行能看到完整 trace |
| M0.6 | 评测骨架：导入 DataMind 改编的 21 条用例 + 规则评分 | M0.4 | 工具名映射和三类处理按 05 §1.1 完成；`python -m eval.run --split dev` 能出结果表；记录 baseline |
| M0.7 | 角色规格 + 语气评测 | M0.6 | 角色规格写入 system prompt；语气规则评分器和 LLM 评审可运行；完成一次人工校准（05 §3.1） |

M0 退出条件：通过 Claude Agent SDK 的真实 DeepSeek 工具往返、可核验 Trace 和可运行评测；离线替身或旧 Messages 探针不能替代 SDK 实测。付费调用按执行计划中的整体授权执行，不逐次询问；缺证据时保留真实验收待办，可先推进与未知 SDK 行为隔离的业务工作，不宣称 M0 全验收通过。
