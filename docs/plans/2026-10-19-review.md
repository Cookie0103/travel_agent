## 1. 用户的产品立场（决定了大部分取舍）

- 只有本人使用：live 额度被刷光（D1）、数据保留/删除（D2）暂缓。
- 酒店流程宽松：超预算只提示不拦；不要为了“已过期/条件变化”反复打扰。币种一律日元。
- 日期必须是今天（东京）及之后，上限今天 + 3 年，其余日期判定不求精细。
- 该问的要问清楚，但**只用一张合并确认卡**，不要多轮追问、也不要卡死。
- 长期偏好必须真的记住并每次带给模型；已有就不再问。
- 酒店**不自动替用户选**；单城市/多城市逻辑一致；所有住宿段选齐才规划；可以在聊天里直接说酒店名片段或贴乐天链接。
- 设计逻辑的改动先问用户；同一个问题连续尝试两三次仍失败要及时停手。

### 2.4 “问清楚再选酒店”新流程（今天的主体）
- 一张合并确认卡（`form.purpose="trip_ask"`）：起床、结束、第一天到、最后一天走、和谁去、（儿童年龄未知时）同行儿童、住宿类型、禁烟、床型、交通；每项都有“无要求/不确定”，时间类可自己填；**已有长期偏好的项（节奏、交通、起床、结束）不出现**。只要城市、日期、成人数、房间数已知就一定发卡（不依赖模型选了什么追问方式）。
- 酒店候选全部展示、不自动选；单城市就是只有 1 个住宿段；选齐才规划；“先不选酒店，先排行程”任何时候可用。
- 聊天里选酒店：贴乐天链接（解析 `f_no`）或酒店名片段（规范化后唯一匹配，多家则列出让用户选，太泛的词不算）；多城市没说城市时出“已自动归到某城市，可以吗？”确认卡（确认/否 + 填城市）。
- 长期偏好：确认过的偏好每次自动带给模型；新增起床/结束时间两种；出草稿后最多一张合并偏好确认卡（默认“记住”）；酒店类偏好/同行人/到达离开时间只算这次；已确认的长期交通视为“已知”（缺失字段不再列交通，条件里不冒充成用户这次说的话）。
- 条件区节奏来源：本次指定 / 长期偏好 / 默认假设。
- 超预算：从“硬冲突（不能确认）”降为“警告”，单城市和多城市选酒店都不再拦。
- 用户可见文本：离线回复里不再露出 `<untrusted_text>` 围栏标签（只在用户可见边界剥掉，模型侧不变）；缺交通方式的提示改中文；金额统一显示 `30,000 JPY`。
- 偏好面板：去掉手动编辑块和画像文字，只留偏好列表（逐条“删除”）、状态标注、折叠的“其他旅行的临时偏好”。

## 3. 真模型（DeepSeek）验证结果

线上部署后用真浏览器 + 真模型多轮复测（逐轮记录见 session-log §6 之后）。结论：

| 场景 | 结果 |
| --- | --- |
| 单城市：一张合并卡 → 查酒店 → 全部展示不自动选 → 聊天说酒店名 → 规划 → 草稿后出偏好确认卡 | 通过 |
| 单城市：超预算草稿可直接“确认保存”，保存后出现“正式行程 · V1”并可导出 ICS | 通过 |
| 多城市：合并卡零回答确认、按段展示、名字片段匹配、“归到某城市”确认卡、选齐才规划、出 4 天草稿 | 通过 |
| 乐天链接指定酒店 | 通过 |
| 已有长期偏好时不再追问交通/节奏 | 通过（修复交通后复测） |
| 偏好面板精简 | 通过 |

没验证到的：没有长期偏好的全新账号（清浏览器登录会丢演示数据，没擅自清）、“同行儿童”分组（真模型这次自己写了无儿童，仅离线测试覆盖）、点“否”后填城市的分支、一家酒店都搜不到时的路径、Claude 原生模型。

## 4. 发现的问题与处理（含没修的）

| 问题 | 状态 |
| --- | --- |
| 合并卡在某次运行里没有出现（模型用文字问了儿童并声称有卡） | 已修：发卡条件去掉 `child_ages`、卡里加“同行儿童”、`update_conversation_state` 返回 `trip_ask_card`（issued/pending/none） |
| 只说酒店名片段（浪華の湯）匹配不上 | 已修：规范化 + 唯一片段匹配 + 歧义列出 |
| 聊天选完酒店后选酒店控件被禁用、计数过期 | 已修：当前“有酒店卡的最近一轮”按服务端状态保持可用 |
| 已有长期交通偏好仍用文字问交通 | 已修 |
| 统一规划按钮在“聊天选 + 按钮选”后保持禁用 | 第三次尝试后恢复正常；**根因未确认**（子代理用真实数据写测试无法复现）；已加“被阻止时显示准确原因”的提示；按用户要求不再继续修 |
| DeepSeek 偶发编造不存在的工具名，被本地守卫停掉本轮（用户再发一句即可继续） | **有意不改**（放宽会动一条安全边界） |
| 草稿依赖的酒店报价/地点证据有 30 分钟有效期，过期后不能确认，要重新生成 | **未动**（用户暂缓评估放宽） |
| 页面重新加载后会同时看到历史块（“已选 0/2 段”，按钮禁用）和当前块 | 设计内但略乱，未处理 |
| 新草稿偶发硬冲突（例如把京都的金阁寺排到大阪的日子） | 校验器按设计拦下，用户可在聊天里让它修正 |
| 旧的几种偏好键（住宿类型、房型、禁烟、同行模式）仍可被模型提成长期，仅靠提示词限制成“这次” | 遗留（评测依赖它们） |
| 酒店偏好里的“有儿童”没填年龄会得到 422 提示；中文数字年龄（“两岁”）被拒 | 遗留 |
| 多城市每段只查约 3 家酒店（为不增加 token 费用），单城市最多 6 家 | 有意 |

- 本机固定 CLI：`.cache/cli-2.1.294/claude.exe`，`.env` 里 `TRAVEL_CLAUDE_CLI` 指向它。清了 `.cache` 要重装（`npm install @anthropic-ai/claude-code@2.1.294` 取 `claude-code-win32-x64/claude.exe`）。

- 线上：三个 Railway 服务的源分支是 `batch/2026-10-19-architecture-hardening`，推送即自动部署；回到旧分支需要在 Railway 里把三个服务的源分支改回 `batch/2026-10-15/latency-optimization`。
- 提交：钩子会跑完整测试约 6 分钟；并行有子任务改文件时容易撞上“测试跑到一半文件被改”，等它们结束再提交。
- 真浏览器验证注意：用 `claude-in-chrome` 时，页面里旧轮次的按钮是禁用的；重新加载页面后用新脚本；元素检查（`find`）说“可用”不等于真的可用，要以 DOM 的 `disabled` 属性和截图为准。
