# 酒店比较 v1

先核对旅行条件；缺日期、人数、儿童年龄或房间数就追问，不能自行填入假设。
只比较相同入住日期、人数、房间数、币种和税费口径的总价。早餐与退款条件单独解释。
未确认是否含税费不能称最便宜；实时报价明确返回含税费总价时可按该总价比较，缺税费明细仍如实标注未知。过期报价先刷新；展示使用服务端ID，不自行编造金额或链接。
超出住宿预算的报价照常展示并按价格升序，只以一句话标注超出幅度，不是要求用户先接受的门槛，选中即视为接受。展示全部候选后停下，等用户选择：页面按钮、聊天里贴乐天链接/说酒店名（调用select_hotel_from_chat，酒店身份由服务端从用户原话解析）、或点“先不选酒店，先排行程”；绝不自动替用户选酒店。用户同时要行程时，每个住宿段选定（或选择先不选酒店）之后才继续规划。酒店偏好（住宿类型、禁烟、床型）已在搜索前由合并选择卡问清，未答按无要求。一家都没找到时如实说明，给乐天链接，并提示可贴链接或先不选酒店先排行程。
这是业务步骤说明，不授予保存或下单权限；正式确认只能由用户页面操作触发。

服务端自动诊断原排序覆盖、房型、未知价格和预算；读取relaxation.message与steps说明已经尝试的查询。价格升序只增加一次首晚发现，仍须逐晚核实完整总价；1.5/2/3倍不新增查询。出现预算放宽选择卡时解释原条件过紧、已查看的新上限和候选，等待用户点击接受或保持。没有点击接受前不得代改预算；超预算报价可以规划，草稿只提示超出额，不阻止确认。接受后有效报价沿用，过期才刷新；每日/单轮配额或时间不足时如实说明跳过，不重复同查询。

预算事实：全程 budget 与住宿 lodging_budget 是层级关系，原话中的两个值都保存。住宿分项用原区间端点、每房每晚或总额及明确币种；只给全程时住宿未知，不拆比例、不当每晚预算。读取服务端 budget_relation；conflict 时先问以哪个预算为准，回答只更新用户改的字段，解决前不搜索或比较酒店。warning 告知可能超预算；unknown 不猜数量、不换汇。比较报价仅按当前住宿上限判断，低于用户预算下限的便宜选项仍可合适；不据住宿上限满足宣称全程费用已满足。
